# AGENTS.md

Ranne bridges a Wear OS watch to an iPhone. It is a fork of
[watch-bridge](https://github.com/DamianDzi/watch-bridge) (MIT), itself derived from
[WearBridge](https://github.com/k97/WearBridge) (MIT). The primary target is a
OnePlus Watch 2 (Wear OS 5) with an iPhone 13 mini (iOS 27), built for its owner first
and for other users second.

## Layout

| Path | What it is |
| --- | --- |
| `apps/wearos` | Watch app. Kotlin, Compose, minSdk 33 (Wear OS 4), Gradle wrapper |
| `apps/ios` | iPhone app. SwiftUI, project generated by xcodegen, deployment target iOS 26 |
| `specs/` | Contracts and design. `health-ble-protocol.md` is the byte-level wire format |
| `docs/` | Setup and test procedures for people |
| `third_party/WearBridge` | Vendored upstream at a pinned commit. Reference only, never edit |

Identifiers: watch `applicationId` is `dev.koit.ranne`, iPhone bundle ID is
`dev.koit.ranne.companion`. The Kotlin package and Gradle `namespace` stay
`com.wearos.ancsbridge`, and the Xcode project and target stay `AncsBridge`. Do not
rename those in passing; it touches every file for no functional gain.

## Read before changing code

1. `specs/design.md` and `specs/health-ble-protocol.md`
2. `CONTRIBUTING.md`
3. The feature matrix in `README.md`

## Build and verify

Watch app (Linux or macOS, needs JDK 17+ and the Android SDK):

```sh
cd apps/wearos
./gradlew test assembleDebug --console=plain
```

iPhone app (macOS only, needs Xcode and `brew install xcodegen`):

```sh
cd apps/ios
xcodegen generate
xcodebuild -project AncsBridge.xcodeproj -scheme AncsBridge \
  -destination "generic/platform=iOS" -configuration Debug \
  CODE_SIGNING_ALLOWED=NO build
```

CI (`.github/workflows/ci.yml`) runs the watch unit tests on Linux and an unsigned
iPhone build on macOS for every pull request. If you cannot run a build locally, push
and read the CI result. Say in the pull request which checks you ran yourself and
which you left to CI.

## Rules

- **One task, one branch, one pull request.** Keep the diff inside the task's scope.
- **No hardware, so test the logic.** Agents cannot pair a watch. Put behaviour behind
  pure, unit-testable seams (codecs, state machines, crypto) and keep Bluetooth and UI
  glue thin. Anything that needs a real device is a human checkpoint: say so, do not
  claim it works.
- **Wire formats are contracts.** Each lives in `specs/` with golden-vector tests on
  both sides. Change one codec and you change the other codec and the spec in the same
  pull request. New record types must be additive: old apps skip unknown types.
- **Honest status.** Anything not confirmed on hardware is "implemented, unverified" in
  the README matrix. A pull request that marks something verified says how.
- **Bluetooth names are part of the protocol.** The iPhone advertises the local name
  `WearBridge` and the watch scanner matches on it. Change both sides together and only
  with a hardware test.
- **Secrets.** Never commit a `DEVELOPMENT_TEAM`, signing files, keystores or keys.
  `apps/ios/project.yml` ships with an empty team on purpose.
- **Licences.** Keep `LICENSE` and `apps/NOTICE.md`. MIT-licensed code may be reused
  with attribution in `apps/NOTICE.md`. Do not copy GPL-licensed code into this repo,
  and do not decompile or copy from closed-source bridge apps.
- **Commits.** Conventional commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`,
  `ci:`, `chore:`). Tests green before review.

## Pull request description

State, in this order: what changed, how it was verified (commands run and their
result), what could not be verified and why, and any open question for the owner.
